# Imaging UI

`XrayCard` integrates with the response catalogue. `XrayScreen` uses the active encounter and the platform photo picker to open an explicitly selected local image. It does not classify or infer findings. It uploads only in live backend mode, and the image's provenance line says so. Every place an image is attached (this screen, the visit's dock, a scan) uploads through one path (`upload.ts`, wired by `use-upload.ts` to the server's `xray.upload`), and a card shows the image model's reading only of its own image's upload (`readingOf`): it waits while the image is being saved, says when the upload failed, and never shows another image's reading. Empty, picker-error, cancelled-picker, loading-image and unreadable-image states are distinct. The original displayed image has no tint, blur or shader. While the image model reads a film (`scanOf`: asked, not yet answered; not while it is still saving), the card's tile and the viewer show a scan layered over it (`scan.tsx`): a beam with a Sobel edge pass and Bayer dots in its wake, corner ticks and "Sona Vision reading…", then one settling pulse and a light haptic when a model's reading lands. The reading is text only, so the scan is global and marks no anatomy; it is mounted only while reading (nothing runs at rest) and is still under Reduce Motion. `/scan-preview` shows it over the bundled film with the states toggled by hand (dev builds, or `EXPO_PUBLIC_SCAN_PREVIEW=true`). Incidental findings (demo flow 6, `features/findings`) appear as numbered rings laid over it, labelled "Unvalidated", never drawn into the pixels. A ring marks only the image it was read from (`onImage`): the authored findings sit on the bundled reference film alone, and a chosen image shows only a model's read of that very upload, or none.

The encounter retains the selected URI for the current app session. Reset clears it; the picker cache is not durable clinical storage. Selection results are ignored if the screen unmounts or the active patient changes while the picker is open.

Response cards render their captured `imagingSnapshot`. Their original-image action opens the saved card by ID and patient ID. The viewer resolves that ID only inside the active encounter, verifies patient and encounter identity, and shows the saved image without edit/analysis controls. Missing snapshots never fall back silently to a replacement image. A separate action opens the current image for new analysis. Retrying an old response is labelled as acting on the current encounter image.

`OriginalImageViewer` accepts a `TeachingImage` with source and provenance. Its pan/pinch transformations run in Gesture Handler/Reanimated worklets. Explicit zoom/reset buttons supplement the gestures. A real-device check is still required for gesture interruption, image sizing and large text.

A CC0 teaching image is bundled; see [asset provenance](assets/PROVENANCE.md). Beside it, `lobar-pneumonia-pa.jpg` (CC0, real adult pneumonia in the right lower zone) is the film uploaded to Amelia Tan's visit for the pitch and by the pre-demo check (`apps/server/test/proving-run.ts`); no screen requires it, and `provenance.test.js` keeps every bundled film credited with the checksum of its bytes. Its uploader's description appears only as a reference summary, explicitly unrelated to the selected patient and not a model result. A user-selected image replaces the reference preview and always shows unavailable findings. The reference description is never applied to a local image. If the bundled fixture is omitted, the missing-image layout remains available.

Picker API checked against installed Expo SDK 57 and [Expo ImagePicker documentation](https://docs.expo.dev/versions/latest/sdk/imagepicker/). No permissions are proactively requested for selecting only still images through the system library picker.

Evidence answers with citations

Where an evidence answer's sources come from, how they are ranked, and how a claim earns its citation. Staging, synthetic patients only.

Citation checks

How a claim keeps its citation

  • sourcedClaims drops a claim that cites nothing it was shown, or a number out of range.
  • quotedClaims keeps a quote only if the cited source contains it word for word.
  • recordedPoints keeps a patient point only if its fact is in the record text.
  • Numbered sources run: the patient's X-ray films, the patient record, PubMed studies, then library passages. Each answer writes a provenance row.

Sources, read at once

Search and ranking

  • PubMed first takes guidelines, systematic reviews, meta-analyses and RCTs with English abstracts, then tops up. Searches and abstracts are cached in Postgres; if PubMed fails, the cache answers.
  • Hybrid search: plainto_tsquery('english') with lexemes ORed, and pgvector cosine on 768-d EmbeddingGemma vectors, 50 each, fused by RRF (k = 60). bge-reranker reorders the fused top 20; the top 3 passages go on.
  • evidence.stream streams search, read, write, bottom line and each claim; evidence.ask returns the whole answer. Sona Pro web and iPhone use it.

Same embed box

X-ray similarity (BiomedCLIP)

  • xray.upload stores the film in R2, indexes its reading as library document xray:<visit> (with Malay and Chinese terms) and stores a 512-d BiomedCLIP vector in image_vectors.
  • xray.similar finds the hospital's nearest films from a film or from text. Only available when sona-embed is named.

Known limits

Not yet

  • No reranker score floor, so weak passages can still be shown.
  • A film's library index includes the patient's name; passages are not de-identified before Sona Med.
  • Laya routing is used only by the iPhone app, and only after the regex router, which sends evidence questions straight here.

Model seam and fallbacks

How a route reaches a model, and what answers when a model is down. Staging only, with synthetic patients; GPU endpoints are often down, so fixtures are common.

Selection (context.ts)

  • No BASETEN_API_KEY: context.models is undefined, every method answers from stubModels
  • Key set: basetenModels maps methods to boxes; a failed call answers from the stub, labelled fixture
  • Key + SAGEMAKER_ENDPOINTS + AWS keys: listed boxes go to SageMaker (invocations, or invocations-response-stream for streamed chat)
  • Every answer carries its origin: { source: "model" } or { source: "fixture", waking? }

Outside the seam, and limits

  • ask.route calls Laya (sona-laya) directly; the library embedder is sona-embed, else Workers AI, else a hashed stub
  • A Baseten key is required even when every box is on SageMaker
  • On SageMaker, wake and health answer 200 locally; a deleted endpoint fails the call and the stub answers with no waking estimate
  • workersModels is written and tested but never wired

Names and timeouts

  • Screens name models from model-names.ts, first match wins: Privacy, Speech, Voice, Vision, Med, else “Sona”
  • Timeouts: 30 s default, 60 s evidence, 90 s scribe draft, 8 s reranker, 5 s Laya, 2.5 s health, 5 s wake
  • Embedder: 3 s per query, 60 s per document batch

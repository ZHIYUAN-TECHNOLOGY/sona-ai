The privacy pipeline — data flow

1

Consent + capture

Doctor toggles consent, taps record. Mic → VAD detects speech.

↓
2

STT — Whisper (on-device)

Audio → raw transcript. Encrypted, stays on device. Malay/English/Manglish.

↓
3

Privacy gate — OpenMed PII (on-device)

De-identifies transcript → de-identified text + a re-ID map that never leaves the device.

↓
4a

Summarize — local LLM (offline path)

Gemma 4 E4B / Qwen3 on-device → SOAP note. 100% private. Airplane-mode works.

🔓
The only thing that may cross the boundary — and only on the optional premium path: de-identified text → TLS → Claude. no audiono namesblocked if redaction unsure
5

Re-identify locally

Re-ID map reapplied on-device — names reinserted into the returned note.

↓
6

Clinical NER + review

OpenMed tags Dx/drug → problem & med list. Doctor edits, every line traces to transcript, signs.

↓
7

Export + audit

FHIR R4 + PDF. Immutable audit log. Raw audio discarded after transcript.

Hard rule (enforced in code, not policy): only de-identified text may ever cross the device boundary; the re-ID map never leaves. Low redaction confidence → cloud send blocked → local-only. This single rule = the PDPA story + the airplane-mode demo.
